# Regram 产品体验审查

2026-10-10 修复跟进：原报告的五项问题已修复并追加模型及应用内回归。以下保留初始审查快照；当前结果与完整矩阵差异见 [功能修复与全量核对](feature-checks.md)。

审查日期：2026-10-10。使用 `product-experience-audit`，检查当前工作区的主要使用链路。本轮只新增报告与审查证据，没有修改产品源码、现有配置或登录账号。

## 结论

**Hold：暂缓将当前版本作为“全部移植功能已验收”版本发布。** 发现 1 项 P1：继承的 Google／Yandex 翻译路径可能在消息编辑后返回旧译文。另有 4 项 P2，涉及译文结构、备份范围、过滤规则输入和语音转写等待。没有确认 P0。

当前版本可以继续开发和测试。主要设置导航的性能已有可信改善证据；这不等于全部功能或全部设备已经验收通过。README 明确说明移植仍在进行，措辞与现有覆盖基本一致。

目标用户：已有 Telegram 账号，希望保留原版 Qt 界面，同时使用过滤、隐私、消息保留、翻译和媒体增强功能的 macOS 用户。成功标准包括找到功能、获得符合当前输入的结果、失败后能恢复，以及正常登录数据量下可接受的交互响应。

环境：Regram 7.3.0 Debug，Qt 6.11.2，Apple M3，macOS 27.0。应用声明最低 macOS 12.0；这只是声明，尚无 macOS 12 实机证明。审查针对已有固定参考版本，不重新同步参考项目或开展竞品研究。

证据等级：**Live-confirmed** 为运行证据，**Code-confirmed** 为源码可达路径确认，**Documented** 为文档声明，**Hypothesis** 为仍需定向验证的风险。引用之前的运行结果均标注“复核既有证据”，不计为本轮新执行。

### PEA-01：旧译文缓存

**源码追踪：** [消息翻译入口](../../Telegram/SourceFiles/boxes/translate_box.cpp) 第 433、461–483 行 → [服务选择](../../Telegram/SourceFiles/regram/nagram/services/translation.cpp) 第 286–305 行 → [继承翻译提供方](../../Telegram/SourceFiles/lang/translate_provider.cpp) 第 48–70 行 → [Ayu 翻译提供方](../../Telegram/SourceFiles/regram/ayu/features/translator/ayu_translate_provider.cpp) 第 110–129 行 → [翻译缓存](../../Telegram/SourceFiles/regram/ayu/features/translator/ayu_translator.cpp) 第 136–177、283–320 行。

**触发条件：** 独立服务选择为“继承”，高级工具中的提供方为 Google 或 Yandex；一条普通服务器消息成功翻译后，收到该消息的编辑，再以相同目标语言打开翻译。此处是源码推导的可达复现条件，本轮没有请求真实翻译服务。

**预期：** 例如原文从“不要支付”改为“现在支付”，再次翻译应对应编辑后的正文。

**实际：** 消息缓存键只有 peer、message ID、源语言和目标语言。读取时虽然已取得当前 `originalText()`，却直接采用命中的 `translatedText`，不比较缓存保存的原文。消息编辑没有改变缓存键。可确认结果存在继续对应旧正文的路径。

**影响：** 用户看到成功译文却可能理解为相反或过时的信息；重新打开翻译也不能保证纠正。进程级缓存还缺少账号身份，但跨账号错误命中的具体场景列为 Hypothesis，不宣称已发生内容泄漏。

**现有恢复：** 切换高级翻译提供方会清空缓存，完全退出应用也会清除进程内缓存；没有针对这条结果的明显“忽略缓存重译”操作。它们是源码确认的恢复机制，未经本轮真实服务验证。

**产品决定：** 保留翻译功能，修正缓存有效性，并在消息正文或实体改变时重新计算。账号身份、提供方和请求配置应参与缓存隔离；不要靠用户切换服务修复结果。

**验收条件：** 使用虚构消息和可控响应，第一次翻译成功后编辑相同消息，关闭并重新打开翻译。第二次结果必须对应新正文；换账号、只改实体以及请求中途切换提供方也不得命中过期结果。覆盖普通消息翻译和继承服务的草稿翻译，不能只测试独立服务模型。

### PEA-02：草稿翻译丢失结构

[Google 实现](../../Telegram/SourceFiles/regram/ayu/features/translator/implementations/google.cpp) 第 91、160–163 行仅使用正文构造请求和结果；[HTML 转换](../../Telegram/SourceFiles/regram/ayu/features/translator/html_parser.cpp) 第 13–26 行也不携带原有实体，Yandex 使用此路径。用户自然输入的命名链接、代码格式和其他手动格式没有得到统一保护。

[应用译文](../../Telegram/SourceFiles/regram/nagram/services/draft_translation.cpp) 第 41–47 行用返回结果替换整个草稿及 tags。预览和取消仍可用，但用户可能只检查译文正文，没有察觉“查看详情”背后的链接已丢失。这里没有确认旧链接目标被回填；问题是原有实体无法保留。

验收：带命名链接、代码、粗体、emoji 的虚构草稿，在不同提供方下应用译文，目标链接及受保护片段保持正确；无法保留时有明确提示，取消后原草稿完整。本轮远端输出质量测试 Blocked。

### PEA-03：备份范围不完整

[导出界面](../../Telegram/SourceFiles/regram/nagram/settings/config.cpp) 第 162–185 行调用 `Exchange::Export(ForDevice(), RegisteredOptions())`；[导出逻辑](../../Telegram/SourceFiles/regram/nagram/core/exchange.cpp) 第 79–120 行只携带注册的设备项。[高级设置](../../Telegram/SourceFiles/regram/ayu/ayu_settings.cpp) 第 39、456–469 行存为独立键 `regram.advanced.settings-v1`，没有进入该注册表。[共享设置](../../Telegram/SourceFiles/regram/settings/shared.cpp) 只桥接六个布尔选项。

高级工具中的翻译提供方、消息保留选择及全局幽灵模式设置因此不能由这个文件完整恢复。当前范围文案排除了账号、消息、凭据和 Telegram 设置，却未明确排除这组 Regram 设备设置。新设备恢复仍需要手工核对；同一设备导入不会直接重置这些遗漏项，不应表述为“导入导致原设置被删除”。

验收：虚构配置中同时修改主设置、高级设置和账号规则，导出预览明确显示纳入／排除范围；全新测试配置导入后，纳入项准确恢复，排除项有可发现的说明。凭据与登录资料继续不应被自动导出。

### PEA-04：指定聊天过滤的输入门槛

[规则编辑器](../../Telegram/SourceFiles/regram/filters/settings.cpp) 第 73–119 行使用多行文本框；[作用域解析](../../Telegram/SourceFiles/regram/filters/scopes.cpp) 第 12–48 行仅接受类型与数值 ID，不能直接处理用户已有的聊天名或链接。这是兼容规则编辑器的限制，不代表其他过滤入口均没有聊天选择。

规则页还并列展示兼容规则、本地规则、全局规则与聊天／话题设置。已有虚构账户截图确认这些入口存在，但没有证明新用户能判断该选哪一种。选择器可自动生成现有编码，无需改变旧文件格式或合并不同规则语义。

验收：普通用户从指定聊天或规则设置页选择聊天／话题即可保存；显示作用范围及规则来源。保留超长、无效、未来作用域的现有保护。

### PEA-05：转写等待没有自动衔接

[单条转写](../../Telegram/SourceFiles/regram/nagram/services/transcription.cpp) 第 605–609 行在音频未就绪时启动下载、显示文字后返回，没有订阅完成事件接着转写。文案明确要求下载完成后再次点击，所以它没有违背自身提示，但给用户增加了可避免的操作。[批量分类](../../Telegram/SourceFiles/regram/nagram/services/transcription_queue.cpp) 第 5–16 行直接跳过未下载项。

已有保护包括：外部上传前说明服务及地址、同一弹层重复点击保护、错误可见、取消中止请求、结果出现在消息内并可复制。改进时应保留这些行为。

验收：选择未缓存的虚构语音并开始，依次展示下载与转写状态；完成后得到结果。取消后不继续提交；重复点击只有一次提交；批量结果逐项说明成功、失败和跳过原因。外部服务已收到的数据及计费能否撤销，仍需服务契约验证，不能由客户端 `abort()` 推断。

## 性能与核心流程

复核 [Debug 点击报告](debug-click-performance.md) 及 [汇总数据](debug-click-performance.json)：原始对照 27 次操作，优化后两轮共 54 次。它们不是本轮新测试。覆盖菜单、原版设置、Regram 设置、外观页、圆角弹层及关闭操作；设置重绘改善可信。

第二轮空闲冷启动，首次设置创建约 48.9 ms。另一次与构建重叠的测试首次创建达 **1.37 s**，必须保留这个异常；它没有推翻空闲对照，却说明繁忙环境响应仍会受影响。主线程重绘耗时不是端到端屏幕呈现延迟或 FPS。

优化目前通过本地 `REGRAM_DEBUG_QT_GUI_LIBRARY` 启用，仅优化 arm64 像素计算，x86_64 部分保持原样。新构建目录未配置此项会使用原 Debug 库；不能把本机改善宣称为所有安装和平台的保证。

| 流程 | 当前判断 |
| --- | --- |
| 启动→登录入口 | 本轮新建独立断网目录，普通 Debug 程序存活 12 秒，日志确认 Metal 探测及窗口 backing store 初始化；没有本轮可视交互确认 |
| 登录后→打开设置→返回 | 复核既有真实数据副本导航证据；没有重新使用真实账号资料 |
| 找到功能→配置 | 有统一入口和搜索；指定聊天规则首先暴露技术编码门槛，高级页仍有重复分类 |
| 翻译→预览→发送 | 预览、原文、取消和草稿变更检测存在；缓存及结构问题影响最终结果。实际发送为 Not tested |
| 转写→等待→结果 | 单条下载等待需再次点击；成功结果提供消息内显示与复制。真实服务为 Blocked |
| 导出→导入→继续使用 | 有原子文件写入、变更预览及配置冲突保护；高级设备配置恢复存在缺口 |

首个主要认知负担是选择正确的过滤／翻译配置入口。首个不可撤回的外部边界是服务接收正文或音频，发送消息则是另一边界；客户端关闭请求不等于远端删除或退费。已观测最长设置等待为构建重叠场景的 1.37 s，外部服务请求允许等待 120 s。最弱恢复点是成功状态下的旧译文，以及用户以为完整的设置备份。
