# 长内容滚动与绘制卡顿

2026-10-10。用户反馈内容较多时偶发卡顿。最初暂停正式安装包构建；用户随后授权 Debug 验证并恢复全平台正式构建。Debug 输出和账号资料副本均隔离，正在使用的应用未被覆盖。

对本机运行的 Debug Regram 做了两次只读采样。第一次主要处于空闲状态；第二次捕获聊天内容、聊天列表和 Qt 文字绘制，包含 `HistoryInner::paintEvent`、`Dialogs::InnerWidget::paintEvent`、`QTextEngine::shapeText` 和 HarfBuzz 调用。采样只描述当时的调用栈，不能等同 FPS、确定某一次卡顿的全部原因或代表全部滚动界面。

已修改的路径：

- 聊天列表原先达到 256 行或 32 MiB 缓存上限后清空全部图像；现在在插入前逐项淘汰较久未绘制的行，保留仍在使用的图像，严格维持容量和内存上限。淘汰时同步释放对应的动画预览缓存。
- 缓存命中同时检查物理尺寸和屏幕缩放，避免切换屏幕时错误复用图像。显式内容刷新和滚动停止后的原有失效行为保留。
- 普通聊天滚动不再执行仅供机器人启动流程使用的首条非空消息扫描；待发送启动命令时仍使用原来的加载及发送条件。
- 独立 Qt Debug 图形库准备脚本增加文字排版与 CoreText 源文件的 ARM64 优化；保留 Debug 标志、符号、断言和检查，保留原始 x86_64 库及共享 Qt 安装。本轮已编译十份纯绘制、缩放和文字排版源文件，原始库未改动。

回归检查已编写：连续跨越缓存预算时每一步仅绘制新进入的行、容量淘汰保留刚绘制的行、定向失效、缩放和尺寸变化、超预算单行、显式清理；另准备五类文字在 DPR 1／2 下的像素、换行和字体度量对照，覆盖中文、拉丁文、双向文本、天城文、组合字符及 Emoji。

验证通过：十项实际缓存回归、四种图像格式的像素对照、十组文字及布局度量对照、隔离整应用 Debug 构建、500 个聊天和 300 条长消息的滚动，以及 312 个真实聊天的列表与设置滚动。临时测试入口和生成项目的输出重定向均已撤回；原始用户可执行文件 SHA-256 未变。

独立 Qt 绘制探针中，1000 帧文字排版及光栅绘制从 250.65 ms 降至 171.94 ms，约减少 31%。像素和布局保持一致。这是指定 CPU 绘制路径，不能等同整应用 FPS。

在 1200×850、DPR 2 的整应用场景中，长消息首次滚动的事件循环间隔 p95 为 25.4→20.3 ms；设置页最长间隔为 50.2→37.5 ms。真实列表最终三轮 p95 为 36.5／21.8／18.1 ms，设置页为 23.3 ms。首次冷加载和偶发长帧仍存在，最终真实数据测试最长出现 66.1 ms；不能宣称已消除全部卡顿。测试目标定位曾修正为可见完整列表，前后数字不作为严格的屏幕帧率证明。

完整数据见 [scroll-performance.json](scroll-performance.json)。正式优化构建及 macOS 12 实机仍须分别验证。
